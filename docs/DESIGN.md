# 설계

## 목표

- 맥에서 Claude Code의 연결을 사내 프록시(HTTP, SOCKS5, Tailscale 경유 등)로 보낸다.
- 명령 하나로 켜고 끈다.
- 새 세션, 실행 중인 세션, 나중에 열 세션에 모두 적용한다.
- npm과 Homebrew로 설치할 수 있다.

## 환경변수 방식을 버린 이유

Claude Code 문서(network-config, settings) 기준으로 확인한 사실은 다음 두 가지다.

1. **SOCKS를 지원하지 않는다.** `HTTPS_PROXY`·`HTTP_PROXY`에는 HTTP 프록시만 넣을 수 있다.
2. **실행 중인 세션에 반영된다는 보장이 없다.** 셸에서 export한 값은 시작할 때 한 번만 읽는다. `settings.json`의 `env`를 바꿨을 때 프록시나 base URL이 실행 중에 바뀌는지는 문서에 없다.

환경변수만으로는 SOCKS와 실행 중인 세션이라는 두 요구를 채울 수 없다. 그래서 프로세스 환경이 아니라 연결 경로를 바꾸기로 했다.

## 구조

```
/etc/hosts 관리 블록 ──▶ 127.0.0.1:443, [::1]:443 (launchd 데몬, root)
                         ├─ sni.js       ClientHello에서 SNI만 읽는다
                         ├─ relay.js     호스트 목록 확인 → 업스트림 연결 → 양방향 파이프
                         └─ upstream.js  HTTP CONNECT / SOCKS5 (도메인 이름으로 요청)
cli.js ── config.js (설정, 0600) · hosts.js (블록 넣기·빼기) · launchd.js (plist) · check.js (터널 확인)
```

| 결정 | 이유 |
|---|---|
| TLS를 종료하지 않고 그대로 전달 | 인증서를 만들거나 신뢰 설정을 할 필요가 없다. 클라이언트는 진짜 서버 인증서를 검증한다 |
| IPv4와 IPv6 hosts 항목을 둘 다 넣음 | IPv4만 넣으면 AAAA 조회로 진짜 IPv6 주소를 받아 릴레이를 우회한다 |
| 업스트림에 도메인 이름을 넘김 | 로컬에서 DNS를 조회하면 hosts 때문에 127.0.0.1이 나와 루프가 생긴다 |
| 설정을 연결마다 읽음 | 다시 읽기(reload) 로직 없이 `set-proxy`가 바로 적용된다 |
| 목록에 없는 SNI는 끊음 | 데몬이 다른 로컬 프로세스의 범용 터널이 되지 않게 한다 |
| 프록시 등록 전에 3단계 왕복 확인(TCP → 터널 → TLS) | 오타나 닿지 않는 라우터가 저장되지 않게 한다. 실패하면 어느 단계에서 막혔는지 보여 준다 |
| `on`은 터널을 확인한 뒤 hosts를 바꾸고, 실제 이름 조회 경로로 한 번 더 확인 | 깨진 경로로 켜면 Claude Code가 아예 연결하지 못한다. 로컬 프록시 루프는 hosts를 바꾼 뒤에야 드러나므로 두 번째 확인에 실패하면 hosts를 되돌린다 |
| 켜진 상태의 설정 변경도 실제 경로로 확인 후 실패 시 되돌림 | `set-proxy` 오타 하나로 Claude Code가 끊기지 않게 한다 |
| 데몬은 포트만 root로 열고 `nobody`로 내려감 | 루프백 443은 root만 열 수 있다(일반 사용자 bind는 `EACCES`, macOS 26 실측). 나머지는 권한이 필요 없다 |
| 데몬 코드는 root 소유 디렉터리에 복사해 실행 | npm·Homebrew 설치 경로는 사용자가 쓸 수 있어, 그대로 실행하면 사용자 권한으로 root 코드를 바꿀 수 있다 |
| 설정 파일은 root:nobody 0640 | `nobody`로 내려간 데몬이 연결마다 읽어야 하지만, 다른 사용자에게 인증정보가 보이면 안 된다 |
| SNI 레코드 4개 상한, 동시 연결 512개 상한 | 로컬 프로세스가 작은 레코드나 루프로 데몬을 묶어 두지 못하게 한다 |
| 자동으로 직접 연결로 바꾸지 않음 | 반드시 사내망을 거쳐야 한다는 목적과 반대다 |
| CLI가 직접 sudo로 다시 실행 | sudo의 `secure_path`에는 nvm·Homebrew 경로가 없어서 `sudo claude-auto-proxy`가 실패한다 |
| Cellar 경로를 opt 경로로 바꿔 plist에 기록 | 버전이 붙은 Cellar 경로는 `brew upgrade` 뒤 사라진다 |
| Node, 의존성 없음 | npm·Homebrew 배포가 단순하고, 데몬이 불러오는 서드파티 코드가 없다 |

## 한계

- 데몬을 시작하는 Node 실행 파일이 사용자 쓰기 가능 경로(Homebrew·nvm)에 있으면, 그 파일을 바꿔치기해 root로 실행되게 할 수 있다. `install`이 감지해 알리며, root 소유 Node로 설치하면 막힌다.
- TLS half-close(한쪽만 먼저 닫기)는 지원하지 않는다. TLS 클라이언트는 거의 쓰지 않는다.
- 실행 중인 세션은 이미 열린 연결이 끊긴 뒤 새 연결부터 바뀐다.
- `/etc/hosts`는 맥 전체에 적용되므로 같은 호스트를 쓰는 다른 앱도 경유한다.
- 로컬 443 포트를 쓴다.
- 기본 호스트 목록 밖의 트래픽(플러그인 다운로드, npm, GitHub 등)은 사용자가 추가해야 경유한다.
